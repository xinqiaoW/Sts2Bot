# 验证与审计边界

## 标签验收

任务须为原生 `Passed`、完整 observation、`combatEnded`，且实际初始构筑、遗物顺序、计数、目标、教师与请求一致。`damage_model/observation.py` 逐张核对升级、附魔和持久状态；协议 3 缺少实际状态回读即拒绝。异常、超时、清理期限错误和隔离任务不进入标签。

生命值必须为整数、满血开战，终局 HP 在合法边界内，`netHpLoss = initialHp - finalHp`，死亡标记与 HP=0 一致。生产起始 70/70；战斗回血抵消净掉血。

最大生命改变仅允许已适配的下降模式：目标为单只咬人卷轴的弱/普通编组，或实际初始牌组含至亮之焰；下降须为偶数，或触及最小值 1。这是字段与机制模式校验，尚不是逐事件追踪证明每次最大生命变化的来源。不能据此宣称任意改血机制均已支持。

## 测试范围

Python 测试覆盖来源历史还原、计数与先古合法性、特殊卡状态、队列租约/去重/原子写入、重试隔离、备份、谱系和训练划分。原生烟测和差分用于验证游戏恢复与终局；少量场景通过不代表所有牌、遗物和怪物组合全量正确。

历史验收材料保留在部署副本的 `evidence/`，如 `card-state-20260910/`、`orobas-replacement-20260910/`、`shared-ancients-20260910/`、`source-versions-20260913/`。这些是当次代码、配置和运行环境的证据，不能把旧测试数写作当前分支重新执行的结果。游戏、原生附件及多数 evidence 不随普通 Git checkout 获得。

当前已有两批固定训练报告，见[训练文档](../train/README.md)。留出误差说明快照内泛化表现，不能证明最优搜索、未见卡牌全覆盖或下一版教师同样准确。
