# 真实 `.run` 构筑导入

来源提供真实战前构筑；卡牌和遗物经过当前规则标准化后，用 CombatSolver 重新生成掉血标签。接受版本及恫吓替换规则见[来源版本](source-versions-and-scheduling.md)。不按真人胜负、掉血或人工评分挑选强构筑。

## 下载与身份

下载器使用公开导出路径 `https://spire-codex.com/api/exports/runs`，每页最多 1,000 份、至少间隔 31 秒。分页时间窗保持不变，完整下载、校验和导入后才推进 `X-Next-Cursor`。实时与历史的共享限流、退避和备份见[来源回补](source-versions-and-scheduling.md)。

`source_runs` 保留完整 JSON、来源 URL、导入修订和报告。来源内容摘要只忽略已明确适配的展示元数据：run_hash、username、has_replay、damage、player_index，以及兼容处理的 is_beta、_spirecodex_damage；实际游戏历史和 build_id 仍严格比较。等价 payload 的审计保留在 `source_equivalences`，未知内容冲突不会自动忽略。

## 重建战前输入

从静默初始牌组加进阶之灾开始，按楼层应用获得、移除、变牌、升级、降级、附魔，以及遗物获得顺序和先古来源。通常先取得战前快照，再应用该层奖励；探寻进入问号房完成变牌等已确认的战前变化有专门处理。

重复牌缺少实例 ID、同层不同类别变化缺少统一时序时，保留一致的解释并与最终牌组、获得楼层和遗物顺序核对。仅使用解释一致的战前多重集；类别内部不穷举任意交错顺序。缺失记录、解释过多、无法核对最终状态或不能确定混合房间战前边界时，保留原因并拒绝相应来源/快照。

升级、附魔和持久状态绑定到每张具体牌并进入构筑身份。真实永久牌组中的特殊牌允许导入；战斗临时生成牌由原版执行，不倒灌到战前输入。详见[卡牌状态](card-state.md)。

遗物计数按已核实合法范围可复现采样，不还原真人计数。同一构筑的 4 个战斗种子保持计数相同。最大生命遗物和指定遗物单独移除；已发生的获得效果跳过，保留其卡牌变化。其他持续效果仍由原版执行，欧罗巴斯之触采用专门替换流程。见[遗物规则](relic-rules.md)、[计数范围](counter-state.md)。

## 对战目标与去重

`source_floor_window_v1` 取同一 `.run` 来源楼层 f−2 到 f+2 实际出现的怪物编组，包含本层、不跨幕、保留原版编组；非战斗层不补成额外战斗。相邻层自身构筑即使无法还原，其明确、合法的战斗目标仍可使用。同一输入重复出现时合并目标，每目标 4 个固定种子。

`build_origins` 保存每个构筑的源局、楼层、计数种子和标准化信息；`target_origins` 保存来源楼层到目标楼层的对应。构筑、目标、种子、教师相同则共享任务，所有来源仍保留。历史范围外未完成任务若被新窗口覆盖可恢复；完成或隔离任务不因回补重做。

## 标签与保存边界

起始统一 70/70。完整终局的 `initialHp - finalHp` 为净掉血，回血会抵消损失，死亡另记；超时和异常不产生标签。`finalMaxHp` 单独保留。原生生命校验只允许已适配的咬人卷轴、至亮之焰等特定最大生命下降模式，不代表已支持任意改血机制，见[验证规则](validation.md)。

`builds/jobs/attempts` 保存输入、教师、种子和原生终局；导入修订通过 `source_import_history` 保存旧报告。协议或教师变化通过明确迁移保留出处，不改写旧标签。训练使用固定快照并按跨来源、共享构筑与变异血缘连通组划分。

真实来源仍存在上传者分布、版本和角色筛选、无法还原历史及未适配状态带来的覆盖限制。标准化构筑并非完整真人原始状态；新增版本也不会消除这些限制。
