# 特殊卡牌与持久状态

2026-09-11：导入修订 `special_cards_saved_state_v8`，原生采集协议 3。第一轮仍只收静默猎手，原版 0.111.0、A10、70/70、无药水，45 张上限和 0–5 张无色牌规则不变。

真实 `.run` 中永久牌组实际拥有的任务牌、状态牌、衍生牌允许导入。任务牌包含藏宝图（SPOILS_MAP）、探寻（DOWSING）、灯火钥匙（LANTERN_KEY）、多尼斯异鸟蛋（BYRDONIS_EGG）。战斗中临时生成的牌仍由原版战斗逻辑生成，不倒灌为战前牌组；变异新增牌仍从原来的普通静默/无色牌池选择。其他角色的永久牌组限制、废弃占位牌、炼制药水牌及既有未适配遗物规则保持。

| 牌 | 还原的原生保存字段 | 历史处理 |
|---|---|---|
| 藏宝图 | SpoilsActIndex | 保留原版第二幕的值 1，默认值使用稀疏表示 |
| 探寻 | RoomsEntered | 问号房进入前推进；到 5 时必须与真实变牌记录对应，战前已经是变成后的牌 |
| 愧疚 | CombatsSeen | 胜利结束后推进，死亡不推进；战前保留已完成战斗进度 |
| 疯狂科学 | TinkerTimeType、TinkerTimeRider | 还原攻击/技能/能力及九种合法附加效果，拒绝不合法组合 |
| 蛋、灯火钥匙 | 无额外保存属性 | 保留卡牌身份，历史中的变牌仍按记录应用 |

升级、附魔和这些字段绑定到具体卡牌。卡牌 ID 一样但状态不一样时，构筑 ID、去重、变异继承与模型联合特征均会区分；空状态不会改变旧无状态卡牌的序列化或构筑 ID。看板会显示进度或效果组合。`persistent_state` 是模型输入，`savedIntegerMembers` 是原生请求，`persistentState` 是原生实际开战回读。原生先创建卡牌，再通过 SavedProperty 的原生属性 setter 恢复状态，然后升级/附魔。缺少协议 3 回读或任何实际输入不一致均拒绝标签。

当前静默范围内的原生 int/enum 保存属性已逐项处理。遗传算法、镰刀的保存字段属于其他角色牌，仍不允许直接作为静默初始输入。未知字段/字段类型、无法确认的同层混合房间时序、无法与最终牌组核对的历史继续记录原因并跳过，不假定为默认状态。原版 0.111.0 以外的字段语义未验证。

正式批次从 `collection-real-runs-v3.sqlite` / `collection-mutations-v1.sqlite` 接续到 `collection-real-runs-v4.sqlite` / `collection-mutations-v2.sqlite`。搜索仍为 Medium、8000 ms、DOP 1、120 秒上限。旧库、旧原生运行目录和全部标签/attempts/隔离记录保留。新库只迁移未完成任务，以 `teacher_batch_origins` 记录出处；`prior_collected_inputs` 保存旧完成/隔离输入的身份与原结果摘要，阻止重审时重采它们，不伪造新协议的完成结果。已完成旧构筑仍可作为一代变异父代。来源报告历史、原 payload、目标窗口、变异谱系与随机序列继续保留。

更新看板时，先对冻结的两个旧 8 秒库做最后一次完整导出，核验包含此前已显示结果；然后使用 `prepare_combined_view.py --freeze-previous` 将其作为独立历史批次并接入新库。之后正常追加新批次。不能直接把新库的未完成接续任务与旧标签重新标为同一个协议，也不能让未采满四种子的面板显示完成。
